Problem and motivation

A pump that keeps running after it loses contact with its tank wastes water and destroys itself.

Project 1 put every decision in one ESP32 and a cloud API. Real water systems are spread out, and nodes fail without warning.

Dry-running pumps

An empty source tank burns out the pump.

Overflow

A full destination tank means water on the floor.

Silent failures

Operators cannot tell which zone went down.

Single point of failure

One controller or router takes the whole system with it.

Our model of it: three reservoirs are the source tanks, the cup is the destination tank, and dyed water stands in for the drinks.

Node 3 · Distribution

Output

  • Cup level sensor
  • Status OLED
  • RGB LED: pump, ready, error
  • Its reading stops the pump
Operator view

Every node is a Wi-Fi access point that hosts the same web dashboard, so it survives the loss of any one node.

No router, cloud service or API is needed: each node that owns an actuator decides locally.

Technical implementation

Wireless

ESP-NOW with our own relay

  • Broadcast frames: no router, no pairing.
  • Sequence numbers drop repeats.
  • A node rebroadcasts what it hears once, so a node out of range is still reached.
  • Heartbeat every second; lost after 3 s.
Data

JSON messages

{"node":1,"seq":145,
 "zone":"pump station",
 "up":80925,"pump":0,
 "lvl":[77,50,77],
 "state":"SAFE",
 "why":"lost Node 2"}
  • Largest message (a full order queue) is about 225 bytes; one frame holds 250.
Interface

Dashboard on every node

  • Each ESP32 serves the page and a JSON status feed over HTTP.
  • Shows nodes alive or lost, levels, pump state, event log and mesh paths.
  • Test buttons run pumps, buzzers and the LED.
  • Order queue: anyone in the room joins the open “Bashy” Wi-Fi and orders a drink from their phone; the operator pours orders in turn with the joystick or the dashboard.

Lessons learned and improvements

What was hard

Engineering challenges

  • A full mesh library was more than three nodes needed; ESP-NOW with a small relay was simpler to reason about.
  • A clicking relay does not prove the pump has power: the pump circuit needs its own test.
  • A joystick does not rest at mid-scale, so it is calibrated at boot.
  • Raw pin readings found GPIO 34 tied to ground, even with a new joystick; the X axis moved to GPIO 32.
  • Electrical noise from the cream pump froze Node 1 with its relay closed; a watchdog now resets it into SAFE with every pump off.
  • Passive buzzers are silent on a plain on/off signal; the alarm needed a real tone.
  • The cup sensor’s 2″ strips cover only part of a 4.5″ cup and are not linear, so every sensor uses a multi-point calibration.
What comes next

Future enhancements

  • Load cell under the cup to pour by weight.
  • Servo pinch valve so SAFE also closes the outlet.
  • Flow check that catches a blocked tube or empty line.
  • Encrypted ESP-NOW and a login on the dashboard.
